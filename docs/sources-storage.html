Source handling

Connect sources without treating them all the same.

RLB can work with local collections, removable media, physical device cards and network-accessible sources. The important distinction is whether the source is durable enough to remain authoritative or must first be preserved.

Source-safe by design: RLB does not modify source folders as part of normal Library analysis. Source material is evidence.

Common source types

Local drives

Existing PC collections can be analyzed from their current storage location.

Removable media

SD cards and other removable sources require stronger preservation handling because they may be reformatted, overwritten or reused.

Network sources

Network-accessible collections can be discovered and analyzed without pretending they are local removable media.

Existing frontend libraries

Collections already maintained by another frontend can remain a useful source of content evidence without RLB rewriting that frontend's own system files.

Preserve removable origins before depending on them

A drive letter such as E: is not durable identity. Different SD cards can appear under the same letter, and a card used for deployment may later be overwritten. RLB therefore treats removable-device origins differently from stable PC or network storage: important content should be preserved to durable storage before the removable source is treated as safely represented.

One Library, many origins

RLB's goal is a single managed view of content without requiring unnecessary duplication of every large collection. Durable sources can contribute Library references and identity while preserved removable content can become durable Library content.

Storage is part of the ecosystem

The Home experience surfaces Library size and storage use because capacity matters when collections span hundreds of gigabytes or multiple terabytes. RLB is designed to make storage choices visible rather than silently copying everything everywhere.
