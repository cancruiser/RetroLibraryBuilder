Reconciliación de preservación

Haz avanzar el contenido reutilizable sin volver al dispositivo original.

La reconciliación de contenido retenido examina contenido ya capturado y verificado dentro de una preservación, determina si ahora puede representarse en la Biblioteca reutilizable, muestra una vista previa y solo cambia el estado de la Biblioteca después de una confirmación explícita.

FLUJO DE RECONCILIACIÓN — FLUJO DOCUMENTADO
1Dispositivo preservadoEmpieza desde una preservación existente con contenido retenido verificado.
→
2AnalyzeLee las pruebas de preservación y el estado actual de la Biblioteca. Sin acceder al dispositivo original.
→
3PreviewRevisa elementos elegibles y resultados previstos: Copy New / Existing / Conflict / Duplicate.
→
4ConfirmNada se aplica hasta que el usuario aprueba el plan.
→
5ApplyEstablece representaciones válidas y registra los resultados reales.
No se necesita el dispositivo original. La reconciliación trabaja a partir del contenido retenido verificado ya almacenado con la preservación y de las pruebas persistentes asociadas.

1. Qué es la reconciliación de contenido retenido

Essential Protection puede conservar contenido junto con una preservación concreta cuando RLB no puede establecer una representación reutilizable aceptable en la Biblioteca durante la preservación.

Más adelante, la Biblioteca puede tener mejor contenido canónico, nuevas reglas de representación o contenido previamente retenido que ya sea elegible. La reconciliación vuelve a evaluar ese contenido preservado.

PRESERVACIÓNContenido retenidoContenido verificado conservado con una preservación porque no se estableció una representación reutilizable.
→
RECONCILIACIÓNReevaluar representaciónDeterminar si ese contenido ya preservado puede representarse de forma segura en la Biblioteca.
→
BIBLIOTECARepresentación reutilizableEstablecer contenido reutilizable solo cuando se cumplen las reglas de identidad y representación.

2. Empieza desde el dispositivo preservado

Abre Device Inspector y localiza la entrada del dispositivo preservado que posee el contenido retenido. La acción Reconcile Retained Content pertenece a ese contexto de preservación.

Diferente de Essential Protection: Essential Protection protege la fuente original. La reconciliación de contenido retenido es trabajo posterior sobre la Biblioteca realizado desde la propia preservación.

3. Analyze es planificación de solo lectura

Analyze examina el conjunto elegible de contenido retenido y el estado actual de la Biblioteca. Predice lo que haría la reconciliación sin establecer todavía nuevas representaciones.

ANALYZEInspeccionar pruebasDeterminar qué elementos son elegibles y qué representación necesitan.
→
PREVIEWMostrar el resultado propuestoPresentar recuentos y resultados antes de Apply.
→
CONFIRMAprobación explícitaEl usuario decide si la reconciliación debe continuar.

4. Lee Preview antes de aprobar Apply

La vista previa hace visible el tamaño y la forma del trabajo propuesto antes de establecer nuevas representaciones.

COPY NEWSe espera contenido nuevoTodavía no existe una representación aceptable.
EXISTINGLa representación ya existeYa debería existir una representación verificada aceptable.
CONFLICT / REVIEWNo aceptar silenciosamenteUna condición de identidad o destino necesita revisión explícita.
DUPLICATE PLAYABLEOmisión intencionalUn duplicado jugable puede omitirse según la regla aplicable.

5. Confirm separa la planificación del trabajo

La reconciliación no debe saltar directamente de Analyze a Apply. Preview existe para que el usuario evalúe si el resultado propuesto tiene sentido.

SOLO LECTURAAnalyze + PreviewInspeccionar contenido y predecir el trabajo.
│
APROBACIÓNConfirmAutorizar explícitamente el plan.
│
ESCRITURAApplyEstablecer representaciones aprobadas y guardar resultados reales.

6. Apply valida el destino real

Los recuentos de Preview son predicciones. Apply todavía debe validar las condiciones reales que encuentra. Por eso el resultado de Apply es la autoridad sobre lo que se estableció, omitió o dejó sin resolver.

Una gran diferencia sin explicar merece investigación. Algunas diferencias pueden ser legítimas, pero una divergencia importante entre Preview y Apply no debe darse por normal sin una razón.

7. Un conflicto de destino no es una representación correcta

Un nombre de archivo igual o un tamaño igual no prueba identidad de contenido. Si RLB no puede establecer la representación de forma segura, el elemento debe quedar como conflicto o revisión, no contarse como éxito.

8. El contenido canónico no siempre es idéntico byte por byte

Para tipos de contenido que admiten representación canónica, RLB distingue la identidad del contenido de la identidad del contenedor externo. Un ZIP canónico puede representar correctamente una carga útil aunque cambien metadatos ZIP, compresión o tamaño total.

9. Duplicate playable es una omisión deliberada

Un resultado Duplicate playable significa que una regla definida evita intencionadamente otra representación jugable. Se mantiene separado de conflictos y errores de importación.

10. Lee el resumen real de Apply

Cuando Apply termina, revisa el resultado persistido, no solo el Preview aprobado antes. Los elementos intentados deben poder contabilizarse entre representaciones establecidas, conflictos/revisión, duplicados omitidos y errores reales.

IntentadosElementos que Apply intentó reconciliar.
=
EstablecidosRepresentaciones válidas establecidas o verificadas.
+
Revisión / conflictoElementos dejados sin resolver.
+
DuplicadosDuplicados jugables omitidos por regla.
+
ErroresFallos reales de ejecución o importación.

11. La reconciliación no vuelve desechable la preservación

La reconciliación trata de si el contenido retenido puede ahora representarse mediante la Biblioteca. No autoriza a borrar manualmente datos de preservación ni a modificar manifiestos históricos.

12. No reconectes el dispositivo original solo para reconciliar

El flujo está diseñado para funcionar sin acceder al dispositivo original. Si una reconciliación de un dispositivo preservado te pide volver a la fuente original solo para analizar contenido retenido, detente y verifica que estás en el flujo correcto.
