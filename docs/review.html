Exception workflow

Let safe work finish. Review only what needs a decision.

Review Center collects import exceptions into grouped decisions so the normal safe import can remain complete while ambiguous or conflicting items wait for explicit review.

REVIEW CENTER — ACTUAL RLB INTERFACE
Core idea: Review does not mean the whole import failed. RLB can complete safe import work while only the unresolved exceptions remain waiting for a decision.

1. What Review Center is for

Review Center is where RLB surfaces import decisions that should not be silently resolved. Instead of forcing the user to inspect every imported item, RLB groups only the exceptions that require attention.

Examples visible in the current Review Center include destination conflicts and cases where an incoming item differs from an existing managed-Library item.

2. Filter the review queue

The top toolbar narrows the queue before you begin making decisions.

SEARCHSearchFind a platform, title, file or review reason directly.

The queue also reports how many decision groups and underlying items match the current filters.

4. Decision Groups reduce repetitive work

The left pane groups items by meaningful context such as platform, content lane and review reason. Each group displays its item count so large problem areas are visible immediately.

A decision group is therefore not a single file. It is a bucket of items that reached Review for the same type of reason.

5. Review reasons explain why RLB stopped

The queue should tell you why an item needs attention rather than simply labeling it “bad.” In the example screen, review reasons include conditions such as:

!
Existing Library Destination Different SizeAn incoming item maps to an existing destination, but the size differs. RLB does not silently assume equivalence.
!
Destination Content ConflictThe destination already contains content that prevents RLB from establishing the incoming item without an explicit decision or defined rule.

6. Select an item inside the group

After selecting a Decision Group, the middle Items pane shows the individual games or assets that belong to that group. Selecting an item loads the detail needed by the Decision Workspace.

This separation keeps navigation manageable even when a single group contains hundreds or thousands of items.

7. Compare before deciding

The right-hand Decision Workspace is where RLB presents the selected item for comparison. The interface explicitly describes the task as comparing the incoming and Library versions before recording the decision.

INCOMINGSource itemThe item discovered by the analyzed import source.
VS
LIBRARYManaged itemThe current version already present in the RLB managed Library.
Why comparison matters: same name, same path or a superficially similar item is not enough evidence to overwrite or equate content automatically.

8. Safe import work remains complete while Review waits

This is one of the most important parts of the Review model. RLB does not require every exception to be solved before preserving the work that was already safe to import.

✓Safe import contentApproved content can complete normally.
+
!Review exceptionsOnly unresolved decisions wait in Review Center.
=
✓Import remains usefulThe completed safe work is not discarded just because exceptions remain.

9. Review is not limited to ROMs

The current queue shows different managed content lanes, including Game Content, Media and Configs. Review therefore protects the integrity of the broader Library, not just playable ROM files.

▣Game ContentPlayable content and game-library conflicts.
▰MediaDisc, composite and other media/asset conflicts.
⚙ConfigsConfiguration content that maps to an existing managed destination.

10. Review history remains tied to import sessions

The Review Center can filter across import sessions, and each decision group carries session context. That allows review work to remain traceable back to the import analysis that produced it.

This is important when multiple imports have been run over time or when the same platform appears in more than one source collection.

Review principles

✓Do not block safe import work just because exceptions exist
✓Keep the reason for review visible
✓Group repetitive exceptions so the queue remains manageable
✓Compare incoming and managed-Library content before recording a decision
✓Do not silently equate or overwrite conflicting content
