Start here

Start by understanding the device.

Device Inspector is the starting point for RLB. Choose the media you want RLB to inspect, run a read-only analysis, review the evidence, and only then move into preservation or deployment decisions.

DEVICE INSPECTOR — ACTUAL RLB INTERFACE
Beta software: Treat original device media as authoritative. A Device Report, a partial preservation, or an available Resume action does not by itself prove that protection completed successfully.

1. Open Device Inspector

Select Device Inspector from the RLB workspace navigation. This is where RLB brings together device identity, preservation state, hardware evidence and deployment readiness.

The screen is state-driven. Buttons and stages unlock as RLB establishes the evidence required for the next step.

2. Choose the device source

At the top of Device Inspector, use Device source to select the media RLB should examine. The interface supports a device source such as an SD card, mounted image or boot folder.

1
ChooseSelect the source RLB is going to inspect. This establishes the input for analysis; it does not itself preserve or deploy anything.

3. Run Analyze

Once an appropriate source is available, run Analyze. Device Inspector describes this as a read-only scan: RLB gathers evidence before write-oriented protection steps become available.

Read-only first: The interface guides the user to run the read-only scan before preservation. Inspection and analysis should not be confused with Apply, Preservation or Deployment.

4. Follow the five-stage workflow

The workflow bar across the top tells you where the current device stands:

1ChooseSelect the source.
2AnalyzeGather and assess evidence.
3PreserveEstablish protection when prerequisites are met.
4Save Device ReportSave the device/evidence report.
5Identity ReadyIdentity state is ready for downstream use.

A stage marked Locked is not an error. It means RLB has not yet established the prerequisite state needed to make that operation available.

5. Read the four status cards

The top status row condenses the major parts of the assessment:

DeviceWhat RLB currently knows about the device and whether it has been analyzed.
FirmwareFirmware evidence and recommendation state.
HardwareBoard, panel and other hardware evidence used for identity.
KnowledgeWhether RLB has enough analysis and preservation information to use its accumulated knowledge.

6. Review the Hardware Identity Assessment

This section is where RLB turns collected evidence into a hardware identity assessment. Before analysis, it may show no match and explain what evidence is still required.

Why this matters: RLB should not identify a retro handheld simply from a product label, volume name or generic operating-system file. Device identity is strongest when it is supported by device-specific evidence such as boot configuration, DTB fingerprints and known hardware relationships.

7. Check the Protection Summary

The Protection Summary separates the state of the system and recovery material from user content. It is derived from preservation state rather than simply assuming that a device is protected because a report exists.

Before protection has been established, the summary can legitimately show states such as Incomplete or Not ready.

8. Use Recommended Actions as guidance

The lower part of Device Inspector tells you what RLB believes should happen next. Before analysis, that may simply be a read-only scan. As evidence and preservation state develop, the recommendations change.

Deployment Readiness is shown separately. This prevents “RLB knows something about this device” from being mistaken for “this device is ready to deploy.”

9. The Actions pane changes with state

The right-hand Actions pane exposes only operations that make sense for the current device state. Disabled buttons show operations that are not yet available.

If RLB finds an existing interrupted or paused preservation, the pane may offer Resume Protection. That is why the example screenshot does not look exactly like a brand-new device.

Do not click Resume just because it is present. Resume is specifically for existing preservation state. A normal first-time workflow begins with selecting the source and analyzing it.

10. A Device Report is evidence, not a backup

Save Device Report records what RLB learned about the device. That report is valuable for historical identity and downstream workflows, but it is not the same thing as a completed, verified preservation.

Protection should be judged from the preservation result and its verification state.
