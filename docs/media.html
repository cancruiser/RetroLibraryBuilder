Managed media

Browse one canonical game. Manage every linked asset.

Media Explorer gives RLB a single place to browse artwork by platform and canonical title, identify missing art, manage preferred covers, and work with the media assets linked to the managed Library.

MEDIA EXPLORER — ACTUAL RLB INTERFACE
Library-first media: Media Explorer is organized around the canonical games and platforms already known to the managed Library rather than treating artwork as a disconnected folder of images.

1. What Media Explorer is for

Media Explorer is the workspace for browsing and managing the artwork and support media connected to RLB’s managed game library.

The screen presents a preferred cover for each canonical game while keeping the broader set of linked assets available for per-title management.

2. Start with the media snapshot

The summary cards across the top provide quick context for the current media library.

3. Browse media by platform

The left-hand Platforms pane is the main navigation for Media Explorer. It supports sorting and platform search, and each platform entry reports how many games and media items RLB currently knows about.

This keeps artwork management aligned with platform identity rather than relying on a flat filesystem view.

4. The game artwork grid shows one preferred cover per game

The center of the workspace is the Game artwork grid. The interface describes it as one preferred cover per canonical game.

That means the grid is a browsing view, not the complete media record for a title. A game can have multiple linked assets even though only one preferred cover is shown here.

5. Search and filter the selected platform

Media Explorer provides title search plus an additional filter control above the artwork grid. This lets the user narrow a platform without leaving the current context.

The artwork-type selector visible beside the missing-art controls can focus the action on a particular asset type, such as Box Art.

6. Missing artwork remains visible

A game with no preferred cover is not silently hidden. Media Explorer can show an explicit ARTWORK MISSING card in the game grid.

▧
Artwork missingThe canonical title exists, but the requested preferred artwork has not been established.

This distinction matters because “the game exists” and “the game has complete media coverage” are two different states.

7. Show Missing Artwork narrows the problem

The top-level Show Missing Artwork action lets the user focus the Media Explorer on titles whose preferred artwork is missing.

There is also a platform-specific control — for example, Show Missing for Atari 5200 — so missing-art review can stay scoped to the platform already being browsed.

8. Find Missing Artwork searches for candidates

Find Missing Artwork is the active acquisition/recovery side of the media workflow. The platform-specific equivalent lets the user run that work for the selected platform.

9. Artwork Sources are configurable

The Add Artwork Source action shows that Media Explorer is not tied to only one media provider or one pre-baked data source. Artwork sources can be added to the media workflow.

The visible ScreenScraper action represents one media-source/integration path available from the workspace. The exact media that can be obtained depends on the configured source and the title being matched.

Source and match are separate concerns: having an artwork provider available does not by itself prove that a candidate belongs to the correct canonical game. Media still needs to remain associated with the right Library identity.

10. Click a title to manage all of its assets

The Media Explorer subtitle explicitly says to click a title to manage all assets. The cover grid is therefore the entry point into a more detailed per-game media record.

A title card also reports its asset count, making it possible to see that a canonical game can have several media files behind the single preferred image shown in the grid.

11. Open Media Folder exposes the managed media location

The Open Media Folder action provides direct access to the media storage location when filesystem-level inspection is needed.

That is useful for inspection and troubleshooting, but the Media Explorer remains the authoritative UI for understanding which media belongs to which canonical Library item.

12. Refresh updates the workspace view

The Refresh action reloads the current Media Explorer state after media work has changed what is available.

The workspace also reports when its view was last updated, helping distinguish the current UI snapshot from media work that may have completed later.

13. Media connects Import, Review and the Library

Media is not isolated from the rest of RLB. Media assets can enter through Import, conflicts can appear in Review, and Media Explorer manages the result against canonical Library titles.

Media principles

✓Organize media around canonical games and platforms
✓Keep missing artwork visible rather than pretending coverage is complete
✓Show one preferred cover without losing the rest of a title’s linked assets
✓Allow configurable artwork sources instead of hard-wiring one provider
✓Keep media conflicts reviewable through the broader Library workflow

What comes next?

Media Explorer makes the most sense alongside the Library workspace, because the canonical titles and platform structure shown here come from the managed Library itself.
