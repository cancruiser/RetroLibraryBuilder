About RLB

A different way to think about retro-device media

RLB started with ROM-library management and has grown into a broader platform for device intelligence, preservation, reusable content and safer deployment.

Why it exists

Many retro handhelds arrive with storage that users eventually need to replace. The difficult part is not writing a new card—it is understanding what was unique or important on the original one, identifying the actual hardware variant, and proving that important content remains protected.

RLB is being built so those decisions can be based on evidence instead of assumptions.

Design principles

  • Original content is treated as authoritative evidence.
  • Preservation should copy and verify rather than delete originals.
  • Device identification should be evidence-based.
  • Same filename or same size is not enough to prove content equality.
  • Reusable content belongs in a verified Library when appropriate.
  • Unique or unrepresented device content should remain tied to its preservation.
  • Analysis should be clearly distinguishable from work that actually changes or establishes data.
  • Frontends and firmware environments should be respected rather than treated as interchangeable emulator containers.

Knowledge Explorer

Retro-device naming can hide significant hardware differences. Knowledge Explorer is intended to make information about handhelds, platforms, boards, firmware, DTBs, boot configurations and device relationships reusable rather than rediscovered from scratch for every card.

As RLB learns from known evidence sources and real devices, that knowledge can improve future identification and deployment decisions.

Current Beta focus

RLB is in active Beta hardening. The current priorities are correctness, reliability, preservation performance, interruption safety, user experience and production readiness. Deployment is the next major workflow after preservation reaches the required acceptance level.

Expect change: Screens, labels and workflows can evolve during Beta. This website will be updated around validated behaviour rather than documenting planned features as though they are finished.

Public project vs application source

The public GitHub repository is the project and documentation home for Retro Library Builder. The application source code is not currently published there. Future source availability and licensing remain separate decisions from the public documentation site.

Community and feedback

Real-world testing is useful during Beta. Useful issue reports include the RLB build/version, the device involved, what operation was running, what was expected, what actually happened, and screenshots or error information where available.
