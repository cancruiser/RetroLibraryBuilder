RLB workspaces

The application, one workspace at a time.

RLB separates content management, device protection, readiness and deployment so each screen can answer a specific question without turning the application into one giant workflow.

MANAGED CONTENT
Import StudioAnalyze sources and approve what enters the managed Library. → Review CenterResolve only the exceptions that need an explicit decision. → Library ExplorerBrowse the canonical games and managed content RLB established. ↔ Media ExplorerManage preferred covers and linked media assets.
DEVICE SAFETY
Device InspectorUnderstand the actual device and its preservation state. → Device ReadinessDecide whether knowledge is strong enough for any deployable target. →
DeploymentExecutes validated targets. Public documentation follows Beta hardening.DOCUMENTATION UPCOMING

Content workspaces

These four screens form the managed-content lifecycle.

LIBRARY
▦
Library Explorer Systems, canonical games, ROM variants, media, BIOS, saves, configs, Library health and safe paging. Explore Library → MEDIA
▰
Media Explorer Preferred covers, linked media assets, missing-artwork workflows and configurable artwork sources. Explore Media → IMPORT
↓
Import Studio Source-safe Analyze → Review → Import → Verify workflow for managed Library content. Explore Import → REVIEW
✓
Review Center Decision Groups, individual items and incoming-vs-Library comparison for unresolved import exceptions. Explore Review →

Device workspaces

These screens decide what the device is, whether it is protected, and whether known deployment targets are actually safe.

DEVICE
◎
Device Inspector Source selection, evidence-based device identity, Protection Summary, recommended actions and deployment readiness. Explore Device Inspector → READINESS
⚒
Device Readiness Canonical identity, targets, confidence, blocking risks and the STOP/not-safe-to-deploy safety gate. Explore Device Readiness →
DEPLOYMENT
⌂
Deployment The application workspace exists, but public workflow documentation will follow the validated Beta deployment path rather than describe unfinished behaviour. Documentation upcoming
