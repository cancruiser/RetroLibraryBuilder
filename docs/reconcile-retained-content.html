Preservation reconciliation

Move reusable content forward without going back to the original device.

Retained-content reconciliation examines content already captured and verified with a preservation, determines whether it can now be represented in the reusable Library, shows a Preview, and changes Library state only after explicit confirmation.

RECONCILIATION WORKFLOW — DOCUMENTED FLOW, NOT A SCREENSHOT
1Preserved DeviceStart from an existing preservation with verified retained content.
→
2AnalyzeRead retained preservation evidence and current Library state. No original-device access.
→
3PreviewReview eligible items and predicted Copy New / Existing / Conflict / Duplicate outcomes.
→
4ConfirmNothing is applied until the user approves the reviewed plan.
→
5ApplyEstablish valid Library representations and record the actual outcomes encountered.

The original device is not required. Reconciliation works from the verified retained content already stored with the preservation and the persisted preservation evidence associated with it.

1. What retained-content reconciliation is

Essential Protection can retain content with a specific preservation when RLB cannot establish an acceptable reusable Library representation at preservation time.

Later, the Library may contain better canonical content, new representation rules may exist, or previously retained content may now be eligible for safe Library representation. Reconciliation is the separate workflow that evaluates that preserved retained content again.

PRESERVATIONRetained contentVerified content kept with a particular preservation because a reusable Library representation was not established.
→
RECONCILIATIONRe-evaluate representationDetermine whether that already-preserved content can now be represented safely in the managed Library.
→
LIBRARYReusable representationEstablish reusable Library content only when the required identity/representation rules are satisfied.

2. Start from the preserved device, not the original media

Open Device Inspector and locate the preserved-device entry that owns the retained content. The reconciliation action belongs to that preservation context.

When you choose Reconcile Retained Content, RLB should make the safety boundary clear: it is analyzing verified retained content, and the original device is not being accessed.

Different from Essential Protection: Essential Protection works to protect the original source device. Retained-content reconciliation is post-preservation Library work performed from the preservation itself.

3. Analyze is read-only planning

Analyze examines the eligible retained-content set and the relevant current Library/destination state. It predicts what reconciliation would do without establishing new Library content yet.

The expected sequence is:

ANALYZEInspect evidenceDetermine which retained items are eligible and what destination/representation each item would require.
→
PREVIEWShow the proposed resultPresent counts and outcomes before the user authorizes Apply.
→
CONFIRMExplicit approvalThe user decides whether the proposed reconciliation should proceed.

4. Read the Preview before approving Apply

The Preview is the user-reviewable plan. It should make the size and shape of the proposed reconciliation visible before any new Library representation is established.

COPY NEWNew Library content expectedAnalyze predicts that an acceptable destination representation does not yet exist and new content will need to be established.
EXISTINGRepresentation already existsRLB expects an acceptable verified representation to be present already.
CONFLICT / REVIEWDo not silently acceptA destination or identity condition needs explicit review rather than being treated as established.
DUPLICATE PLAYABLEIntentionally skippedA playable duplicate can be skipped according to the applicable reconciliation rule.

The Preview may also show the overall eligible item count. The outcome buckets should explain how RLB expects those eligible items to be handled.

5. Confirm is the boundary between planning and work

Reconciliation should not jump directly from analysis into Apply. The Preview exists so the user has a chance to decide whether the proposed result makes sense.

READ ONLYAnalyze + PreviewInspect preserved retained content and predict the Library work.
│
USER APPROVALConfirmExplicitly authorize the reviewed plan.
│
WRITE ORIENTEDApplyEstablish approved Library representations and persist actual reconciliation results.

6. Apply validates the destination it actually encounters

Preview counts are predictions based on evidence available during Analyze. Apply must still validate the destination conditions it encounters when the work actually runs.

That means the actual Apply result is authoritative for what was established, skipped or left unresolved.

PREVIEWPredicted outcomeWhat Analyze believes should happen before the work begins.
≠
APPLY RESULTActual outcomeWhat RLB was able to establish after validating the real destination state during Apply.
Do not dismiss a large unexpected difference. Some divergence can be legitimate when destination state or Apply-time validation changes the result. A substantial unexplained divergence between Preview and Apply should be investigated rather than treated as normal.

7. A destination conflict is not a successful representation

If Apply finds destination content that prevents the required representation from being established safely, that item belongs in a conflict/review result rather than being silently overwritten or counted as represented.

!
Existing destination is not enoughA matching filename or occupied path does not prove that the destination safely represents the retained source content.
!
Same size is not enoughContainer length or byte length alone is not a sufficient content-identity rule where cryptographic or canonical verification is required.
!
Unresolved stays unresolvedIf RLB cannot establish representation, the result must remain visible for review instead of being converted into false success.

8. Canonical content does not always look byte-for-byte identical

For content types that support canonical representation, RLB distinguishes content identity from the identity of the outer container.

A canonical ZIP can legitimately represent a source game payload even if ZIP metadata, compression or total container length differs. The representation rule must verify the required payload relationship rather than relying on outer-file size alone.

SOURCE PAYLOADWhat needs representationThe game/content identity established for the retained item.
→
VERIFYCanonical relationshipProve that the Library representation satisfies the applicable representation rule.
→
REPRESENTEDSafe Library reuseThe Library can represent that source content without requiring a byte-identical outer container.

9. Duplicate playable is a deliberate skip, not an error

A duplicate-playable outcome means the applicable rule intentionally avoids establishing another playable representation. It should remain distinguishable from both conflicts and import errors.

✓Established / representedThe required Library representation was successfully established or verified.
↷Duplicate playable skipIntentionally skipped by a defined duplicate-playable rule.
!Conflict / reviewRepresentation was not safely established and requires review or a defined rule.
×Import errorThe attempted operation failed for an execution/error condition rather than a deliberate review rule.

10. Read the actual Apply summary after the run

When Apply completes, review the persisted result rather than relying on the Preview you approved earlier.

The result should make it possible to account for the attempted items across successful representation, review/conflict skips, duplicate-playable skips and any true import errors.

11. Reconciliation does not make the original preservation disposable

Reconciliation is about whether preserved retained content can now be represented by the reusable Library. It is not an instruction to manually delete preservation content or alter historical preservation manifests.

Leave preservation data and persisted evidence under RLB's control. A conflict in reconciliation means the Library representation was not established for that item by that Apply; it is not permission to discard the retained preservation copy.

12. Do not reconnect the original device just to reconcile

The workflow is deliberately designed so the original device does not need to be accessed. If a preserved-device reconciliation unexpectedly asks you to browse or reconnect the original source merely to analyze retained content, stop and verify that you are in the correct workflow.

✓
Use preserved retained contentAnalyze from the preservation and its persisted evidence.
×
Do not touch the original deviceRetained reconciliation should not require returning to the original media.
