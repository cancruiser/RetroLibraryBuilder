SOURCE / PORTABILITY EXPANSION

Physical-device import expansion

Import can correlate a selected local drive root to readable sibling volumes on the same physical media. Inaccessible partitions are warned, not silently counted.

Network import discovery

RLB supports bounded read-only discovery of known network sources from deployment profiles, prior continuation state and Windows remembered/connected SMB resources.

Lakka portability parity

RLB recognizes Lakka user-data shares including Savefiles, Savestates, Configfiles, Joypads, Remappings, Playlists and Services, retaining native share identity for safe replay.

These newer source/import changes do not rewrite the frozen physical-deployment acceptance labels. The site keeps deployment acceptance, source/import coverage and cross-firmware portability as separate claims.
STILL EXPANDING

Handheld deployment

Handheld support remains a separate deployment-acceptance scope and is not inferred from the Raspberry Pi SBC passes.

Firmware/source parity

Physical media, network sources and Lakka user-data handling have expanded, but full source/import acceptance remains firmware- and layout-specific rather than being assumed from Deployment acceptance.

Advanced canonical import identity

The active staged import workflow is source-safe, but deeper canonical identification and equivalent results across every archive/source form must be validated before broader claims are made.

Documentation rule: Public documentation describes verified capabilities and acceptance outcomes, not internal development identifiers. A feature is described as accepted only when tested behaviour supports that claim.
