Library workflow

Analyze first. Import only what was approved.

Import Studio is RLB’s controlled path for bringing games, BIOS, media, saves and configuration into managed Library lanes without changing the original source. It can work with folders, archives, readable volumes from the same physical device and known network shares.

IMPORT STUDIO — ACTUAL RLB INTERFACE
Source-safe workflow: RLB reads selected sources to discover and analyze them. Approved content is copied into managed destinations; originals are not renamed, moved or deleted.

1. What Import Studio is for

Import Studio brings content into the managed Library through explicit source selection, discovery, analysis, review, import and verification boundaries.

▣GamesPlayable content intended for managed Library organization and later reuse.
◫BIOSSystem firmware/support files tracked separately from game content.
▰MediaArtwork and related media assets.
↓SavesUser save and save-state content.
⚙ConfigurationFrontend, controller, playlist and related configuration content where supported.

4. Physical-device source expansion

When the user selects a local drive root, RLB can correlate that volume to the underlying physical disk and add other readable sibling volumes that Windows proves belong to the same device. This prevents an import from silently seeing only one mounted partition of a multi-volume SD card.

Discovery only: physical-device expansion does not mount partitions, write to the device, rename files, move files or delete files. Partitions that Windows cannot read remain outside the import and are reported as warnings instead of being treated as successfully analyzed.

5. Find Network Sources

Import Studio can perform bounded, read-only network-source discovery. It deliberately does not sweep the local subnet. Candidate roots come from information RLB or Windows already knows:

  • RLB's proven Deployment network profiles;
  • the last proven network continuation for the active Deployment context;
  • Windows connected or remembered SMB disk resources.

Every discovered candidate is read-probed before it is offered as ready. If a device uses a custom hostname or share name, the user can still enter the network path manually.

Current firmware-aware discovery: the network discovery path understands the accepted SBC firmware families, including Batocera, Recalbox, RetroPie and Lakka.

6. Lakka user-data parity

Lakka exposes important user data across separate Samba shares rather than keeping everything beneath a single ROM tree. Current source routing recognizes Lakka save and configuration shares so a Lakka source is not reduced to ROMs alone.

Recognized native user-data shares include Savefiles, Savestates, Configfiles, Joypads, Remappings, Playlists and Services. RLB retains the native share qualifier in managed paths so same-firmware replay can target the correct sibling share later.

Portable does not mean guessed. RLB remains fail-closed where a save cannot be safely translated between firmware layouts without proven game/system identity.

7. Analyze Sources before importing anything

Analysis inventories the readable source and creates the information required for Review Import. It can identify source roots, ROM/BIOS targets, media/assets, save/config lanes, infrastructure exclusions and traversal diagnostics.

Why analyze first? RLB needs a complete picture of the selected readable sources before the user can meaningfully review what should enter the managed Library.

9. Verify & Report closes the workflow

After approved copying completes, verification and the completed import report provide the durable result consumed by later Library and preservation workflows.

10. Current Beta boundary

The active workflow is documented as source-safe and staged. RLB does not use the existence of physical/network discovery as proof that every firmware/source layout or every advanced canonical identification path has reached full acceptance. Those claims remain evidence-driven and are expanded only as the matching tests and physical passes are completed.
